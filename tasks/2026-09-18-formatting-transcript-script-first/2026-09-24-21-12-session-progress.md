### Пункт 1 — параллельные чанки (пункт 3 анализа)
- `formatting-transcript/format_transcript.py`: `fold`/`normalize` и `CHUNK_LINES` убраны. Вход — слова исходника (`split()`), чанки режет `split_chunks`: `CHUNK_WORDS = 300` (эквивалент прежних 20 строк), граница сдвигается к ближайшему концу предложения (`SENTENCE_END_RE`) в окне `SNAP_WINDOW_WORDS = 60`, иначе режется по целевой точке; хвост короче половины чанка прирастает к последнему. У чанка `before`/`after` — по `CONTEXT_WORDS = 50` слов исходника соседей.
- Схема ответа: `{"text": str, "starts_paragraph": bool}`. `format_chunk` (вместо `process_chunk`/`chunk_with_retry`, эхо-детектор удалён) ретраит пустой `text` и двойную обёртку (`WRAPPED_RE`: ```` ``` ```` или `{"text":` внутри `text`); `retry_notice` называет причину прошлой неудачи.
- `format_all_chunks`: первый чанк отдельно (прогрев кэша), остальные — `ThreadPoolExecutor(WORKERS = 3)`, порядок по входу.
- `join_chunks(chunks, outs)`: если предыдущий кусок кончается без знака конца предложения — склейка пробелом и `_continued` опускает заглавную первого слова (только если в исходнике оно строчное и модель его не меняла); иначе `\n` при `starts_paragraph`, пробел — без.
- Отчёт потерь теперь по чанку: слова `chunk` против `text`.
- stderr без поблочного прогресса: журнал вызовов, отчёт потерь, итог «OK: чанков, время, слов». Ретраи печатаются строкой на попытку.
- `formatting-transcript/chunk-prompt.md`: разделы «Вход»/«Выход» под новый контракт, новый раздел «Края чанка» (продолжение предложения из `context_before` со строчной, не закрывать точкой обрыв, продолжающийся в `context_after`, стык-повторы правятся только внутри своего чанка); раздел про разрез `write`/`buffer` удалён; self-check переписан (границы, сохранность, нет пересказа, формат).

## Замечания для следующего агента

- Thinking не выключать ради скорости: без него haiku выбрасывает целые фразы (замер в комментарии у `THINKING`). Промежуточного режима в `claude -p` нет: `--effort` на haiku не действует, `MAX_THINKING_TOKENS` работает только как 0.
- Лимит подписки реален: полный прогон эталона с thinking — ~6 вызовов по 15–25k выходных токенов; прогон на пуле по 3 уже однажды упёрся в 429. Эксперименты экономить, между прогонами проверять выход, а не гонять пачкой.
- Долгие прогоны (~6–10 мин) запускать с таймаутом Bash 600000 или в фоне.
- Отчёт потерь — предупреждение, решение пользователя этой сессии; не превращать в гейт/ретрай.
- Паразиты доводить не надо — решение пользователя этой сессии.
- Разброс haiku между прогонами больше эффекта правки промпта: выводы — только по нескольким прогонам и по воспроизводимости дефекта.
- Примеры для промпта сверять с исходником, а не с diff: difflib на перестановках показывает ложные «выпадения»; смотреть и difflib-метрику, и мультимножественный отчёт потерь.
- `FILLERS` («а», «вот», «ну», «значит») вычитаются целиком по числу вхождений — смысловая потеря таких слов в отчёт не попадёт, сознательный размен.
- `_continued` в полностью строчном входе опускает регистр и у имени собственного в начале шва — осознанный размен, описан в докстринге.
- Константы для экспериментов подменять при запуске (`import format_transcript as ft; ft.WORKERS = 1; ft.THINKING = False; ...`), не править файл.
- Стоимость сравнивать в одном состоянии кэша: правка `chunk-prompt.md` сдвигает префикс (первый вызов после правки — кэш-запись ~62–65k против ~13–30k).
- Лекция публичная — цитаты допустимы в промпте и документах задачи; приватные записи — нет.
- Вне скоупа по анализу: `--bare`, тесты с фейковым `claude -p`, смена пути запуска в transcript-cleanup.
