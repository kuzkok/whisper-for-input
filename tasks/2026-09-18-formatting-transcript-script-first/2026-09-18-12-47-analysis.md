# formatting-transcript: переработка в скрипт-first форму (тонкий скилл)

Дата: 2026-09-18
Статус: постановка (направление согласовано, конкретный объём уточняется по ходу)
Смежная задача: `2026-09-17-transcript-cleanup` (в её брейншторме согласовано это направление; её форма — эталон)

## TL;DR

formatting-transcript почти не используется: механические итерации внутри скилла забивают контекст сессии, прогоны долгие, результат средний. Перевести скилл в тот же ключ, что принят для transcript-cleanup: SKILL.md — тонкая обёртка, запускающая скрипт одной командой; вся механика и весь вывод остаются в процессе скрипта.

## Что не так сейчас

Симптомы (со слов пользователя, без фиксации причин — их предстоит снять):

- контекст сессии забивается: SKILL.md длинный, путь к скрипту разрешается двумя realpath-вызовами (`formatting-transcript/SKILL.md:14-22`), сессия видит stderr прогона и участвует в разборе сбоев;
- долго: чанки обрабатываются последовательно, каждый `claude -p` поднимает полный каркас Claude Code (~9k cache_creation токенов обвязки на вызов, `formatting-transcript/SKILL.md:85-89`), на 20-чанковом транскрипте это 20 подъёмов;
- результат средний: качество выходного текста не оправдывает затраты (Iron Law «только точки и запятые» — гипотеза-кандидат, но это отдельная политика правок, менять её без отдельного решения нельзя).

Отметка: чанковый цикл уже живёт в `formatting-transcript/format_transcript.py:139-179` — LLM-оркестрации в скилле нет, проблема именно в обвязке вокруг запуска и в цене вызовов.

## Целевое состояние

- SKILL.md по образцу transcript-cleanup: триггеры, когда НЕ использовать, literal-путь запуска одной командой (установка симлинком папки в `~/.claude/skills/formatting-transcript`, как решено для transcript-cleanup в `2026-09-17-transcript-cleanup`), без чтения промежуточных результатов и разбора stderr в сессии.
- Правка install.sh: симлинк скилла рядом с transcript-cleanup.
- Стоимость/скорость вызовов: рассмотреть укрупнение чанков и/или `--bare`-режим (`formatting-transcript/SKILL.md:89`) — решение по итогам замеров, не вслепую.
- Политика Iron Law не меняется: качество текста — отдельное решение, в эту задачу не входит.

## Риски

- regress по удобству: сейчас скрипт находит себя в двух местах (проектный и пользовательский скилл) — перевод на симлинк должен сохранить хотя бы один канонический путь без правки SKILL.md руками.
- `--bare` требует ANTHROPIC_API_KEY вместо OAuth/keychain — не включать по умолчанию, пока не подтверждено, что пользователь готов к ключу.

## Задачи (по приоритету)

1. `критично` — снять трассировку одного реального запуска скилла из сессии Claude: сколько вызовов Bash, что попадает в контекст, где уходит время. Без этого остальное — догадки.
2. `критично` — утоньшить SKILL.md до тонкой обёртки (триггеры, anti-triggers, literal-путь, одна команда) + install.sh: симлинк `formatting-transcript/SKILL.md:14-22` → заменить разрешение пути.
3. `важно` — замеры вызовов: стоимость/латентность текущего размера чанка (`format_transcript.py:21`) против укрупнённого и против `--bare`; выбрать по цифрам.
4. `желательно` — синхронизировать стиль SKILL.md с итоговым SKILL.md transcript-cleanup (единый шаблон тонкой обёртки в монорепо).

## Критерии приёмки

1. Запуск скилла из сессии Claude — ровно один вызов Bash с literal-путём; в контекст сессии не попадает ничего, кроме команды, финального пути к файлу и exit code.
2. Скрипт продолжает работать напрямую из шелла без Claude: `python3 format_transcript.py <source> [output]` без правок окружения.
3. Верификация ±2% по словам и коды возврата (0/1/2) сохранены без изменений поведения (`format_transcript.py:171-179`).
4. По пунктам стоимости (задача 3) есть замеры «до/после» в чекпоинте: токены и время прогона на одном и том же транскрипте.
5. Установка воспроизводима на чистой машине: `install.sh` создаёт симлинк, скилл доступен по триггеру без ручного копирования файлов.
