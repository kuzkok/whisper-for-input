# Скилл transcript-cleanup: чистка диаризованного транскрипта с проектным контекстом (черновик)

Дата: 2026-09-17, дополнен 2026-09-18 по итогам брейншторма (двухфазная схема, скрипт-first, вывод спикеров из содержания).
Статус: черновик (политика правок требует обкатки на реальных встречах до фиксации)
Смежная задача: `2026-09-17-diarize-asr-hints` (источник входа: `/diarize` с ASR-подсказками снижает долю ошибок, но не убирает их)
Смежная задача: `2026-09-18-formatting-transcript-script-first` (переработка formatting-transcript в тот же ключ скрипт-first; её SKILL.md — эталон тонкой обёртки для пункта 4 ниже)

## TL;DR

Утилита рядом с `formatting-transcript/`: берёт сырой транскрипт вида `[HH:MM:SS] [SPEAKER_XX] текст` (выход `cli/diarize.sh`) плюс проектный контекст-файл и выдаёт причёсанный транскрипт: имена вместо `SPEAKER_XX`, исправленные ASR-ошибки терминологии, пунктуация. Двухфазная схема: (1) карта спикеров одним вызовом LLM по скелету встречи, подстановка имён — детерминированная замена скриптом; (2) чанковая чистка текста. Форма — скрипт-first: вся механика в CLI-скрипте, скилл — тонкая обёртка, запускающая его одной командой. Отдельный скилл, а не режим `formatting-transcript`, потому что их политики правок несовместимы: у formatting-transcript Iron Law «ни одного изменённого слова», здесь исправление слов — вся суть. Черновик: границы «что можно править» сформулированы, но не обкатаны.

## Контекст

Реальные проблемы свежего транскрипта встречи (40 минут, 6+ спикеров):

- спикеры: часть `SPEAKER_XX` / `UNKNOWN` не сопоставлена, при этом контекст реплик опознаёт человека (обращения по имени, вопрос-ответ, предмет обсуждения);
- терминология: англицизмы распознаны кириллицей («кувер/кубер» → Kubernetes, «токер» → Docker, «пайтер» → Python), жаргонизмы («обмордочка» → веб-морда, «верталка» → виртуалка, «айдичник» → ID-шник), аббревиатуры со слуха и омофонные ошибки малой редакционной дистанции (примеры из реального проекта — в репо не попадают, см. «Конфиденциальность»);
- локальные слипшиеся куски без пунктуации (целая реплика одним потоком);
- при этом основная масса текста уже нормальная — чистка точечная, не сплошная переписка.

Реальный контекст-файл проекта-потребителя живёт вне репо (приватный) и задаёт структуру: таблицы «обращение в речи → имя для транскрипта» по сторонам (наша / заказчик), правила различения тёзок по темам, глоссарий (канонические аббревиатуры; термины латиницей; пары «как распозналось → как писать»; спорные пары «проверять по аудио»). Номера `SPEAKER_XX` нестабильны между записями — прямого соответствия «номер → имя» не существует в принципе, сопоставление только по содержанию реплик.

Опыт `formatting-transcript`: механические итерации внутри скилла забивают контекст сессии, работают медленно, результат средний. Отсюда форма скрипт-first: один процесс скрипта делает всё сам (вызывает `claude -p` на фазы и чанки), сессия Claude не участвует в итерациях и не получает промежуточные результаты.

## Граница политик

| | formatting-transcript | transcript-cleanup |
|---|---|---|
| Вход | монолог, автокапшены | диаризованная встреча |
| Слова | не менять вообще | исправлять ASR-ошибки по глоссарию и контексту |
| Структура | произвольные абзацы | реплики с таймкодами сохраняются как каркас |
| Пунктуация | только `.` и `,` | любая (`?`, `!`, `—`, `«»` тоже) |
| Сомнительное | — | не править без опоры; неопознанный спикер остаётся SPEAKER_XX |

## Дизайн-решения

Форма:

- Самостоятельный CLI-скрипт на stdlib: `cleanup_transcript.py <source> <context-file> [-o out] [--yes]`. Запуск напрямую из шелла возможен вообще без Claude; `--yes` — неинтерактивный прогон.
- SKILL.md — тонкая обёртка: триггеры, когда НЕ использовать, формат контекст-файла, literal-путь запуска одной командой (по образцу двух realpath'ов из `formatting-transcript/SKILL.md` — чтобы статический анализатор пермишенов не переспрашивал). Ни чтения чанков, ни ретраев, ни разбора stderr в сессии.
- install.sh кладёт симлинк папки скилла в `~/.claude/skills/transcript-cleanup`; репо — источник правды; скрипт запускается из репо, как `cli/diarize.sh`.

Фаза 1 — карта спикеров:

- Один вызов LLM (sonnet). Вход — скелет всей встречи: `[HH:MM:SS] [SPEAKER_XX]` + первые ~25-30 слов реплики. Покрытие всех спикеров важнее полноты реплик: обращения обычно в начале реплики, связка вопрос-ответ видна по первым словам, токенов в 3-4 раза меньше, запас на встречи 2ч+ без чанкования карты. Альтернатива «первые N минут целиком» отвергнута: спикер, впервые заговоривший позже, не опознается даже при явной опоре.
- Выход — JSON: `SPEAKER_XX → {имя | null, опоры: [{таймкод, цитата, тип сигнала}]}`. Типы опор: обращение + ответ (по имени спросили — следующий отвечающий и есть этот человек); вопрос к отсутствующему (следующим высказывается он); самопрезентация / роль; предметная область речи (правила различения тёзок из контекст-файла); упоминание в третьем лице. Опоры нет — спикер остаётся `SPEAKER_XX`, имя не угадывается.
- Скрипт печатает карту таблицей, подтверждение по stdin (принять / править руками / выйти). Не-tty без `--yes` — отказ с сообщением.
- Подстановка имён в метки — детерминированная замена строк скриптом; LLM метки не переписывает. Это делает согласованность имён структурным инвариантом: один `SPEAKER_XX` — одно имя на весь выход.

Фаза 2 — чистка текста:

- Вход — транскрипт с уже подставленными метками. Чанкование по репликам: ~40 реплик на чанк, реплика — атом, между репликами не режем; 2-3 предыдущие реплики прикладываются контекстом только для чтения (терминология и тема продолжаются через границу чанка).
- Модель (haiku) возвращает JSON-массив очищенных текстов: по строке на реплику чанка, в том же порядке. Каркас (таймкоды, метки) через модель не проходит вовсе — скрипт сшивает выход сам: `[таймкод] [метка] текст`. Неверную метку невозможно получить, потому что её не просили.
- Верификация чанка: длина массива == числу реплик чанка, нет пустых строк; расхождение — ретрай (кап 2, по образцу эхо-детектора `formatting-transcript/format_transcript.py:109-115`).
- Политика правок текста: можно — пары глоссария (включая «как распозналось → как писать»), англицизмы латиницей в каноническом виде, очевидные омофоны малой редакционной дистанции, любая пунктуация и заглавные (цель — читаемая реплика, не статья с Iron Law). Нельзя — пересказ, сокращения, «улучшение» стиля; слова-паразиты остаются («э», «ну»); обращения по имени внутри текста реплик не нормализуются — «Аня, посмотри» остаётся дословным при метке «Анна Соколова ...»; спорные пары («проверять по аудио») не трогать; реплики не склеивать, не удалять, не разрезать.
- Контекст-файл подмешивается в каждый вызов обеих фаз.

Механика вызовов — по образцу `formatting-transcript`: `claude -p --tools ""` с `--json-schema` (`formatting-transcript/format_transcript.py:38-63`), таймаут и бюджет на вызов.

Верификация финальная (структурная, не по словам): число реплик и множество таймкодов выхода == входу; метки == результату детерминированной подстановки фазы 1. Совпало — exit 0, расхождение — exit 1. Дельта длины текста по чанкам — в stderr, мягкий ориентир для ручной выборочной проверки, не гейт. Существующий выход не перезаписывается.

Модели: фаза 1 — sonnet (вывод имён — тонкая задача), фаза 2 — haiku (глоссарные замены и пунктуация механичны); константы в скрипте, обкатка покажет.

Конфиденциальность: репо публичный — проектная специфика потребителя (названия компаний и систем, имена людей, глоссарий, пути) в него не попадает. Тестовые фикстуры и примеры в SKILL.md — синтетические по мотивам структуры реального контекст-файла (те же секции, выдуманные проект, люди и термины).

## Задачи (по приоритету)

1. `критично` — `map-prompt.md`: правила вывода карты спикеров (типы опор, обязательная цитата + таймкод, различение тёзок по темам, нет опоры → SPEAKER_XX), формат входа/выхода, JSON-схема.
2. `критично` — `chunk-prompt.md`: политика правок текста (можно/нельзя, классы ошибок с примерами), формат входа/выхода (массив текстов, read-only контекст краёв).
3. `критично` — `cleanup_transcript.py`: скелетизация, фаза 1 + подтверждение карты, детерминированная подстановка, чанкование по репликам, вызовы `claude -p`, обе верификации, отказ перезаписи, `--yes`.
4. `важно` — SKILL.md (тонкая обёртка) + правка install.sh (симлинк); формат контекст-файла с синтетическим примером.
5. `желательно` — тесты без реального LLM: синтетическая фикстура (транскрипт с SPEAKER_XX и заведомыми ошибками + контекст-файл), мок `claude -p`, проверка скелетизации, чанкования, подстановки, обеих верификаций (по образцу `formatting-transcript/tests/`).
6. `желательно` — обкатка на 2-3 реальных встречах с разными глоссариями; найденные нарушения политики — обратно в промпты. По итогам снять статус черновика.

## Критерии приёмки

1. На транскрипте, где связка «обращение по имени + ответ» позволяет опознать спикера, карта содержит имя с опорой (таймкод + цитата); спикер без опоры остаётся `SPEAKER_XX` и в карте, и в выходе.
2. Согласованность имён: каждый `SPEAKER_XX` получает ровно одно имя по всему выходу или остаётся `SPEAKER_XX` везде (следствие детерминированной подстановки; проверяется тестом).
3. Число реплик и множество таймкодов на выходе идентичны входу; метки идентичны результату подстановки; скрипт возвращает 0 при совпадении и 1 при расхождении.
4. Термины из глоссария контекст-файла в выходе в каноническом виде (проверка по синтетической фикстуре с заведомыми ошибками).
5. Ни одна реплика не удалена, не склеена с соседней и не разрезана (следует из критерия 3, проверяется тестом верификации).
6. Обращения по имени внутри текста реплик сохранены дословно.
7. Тесты скрипта зелёные с замоканным `claude -p`; неинтерактивный прогон с `--yes` работает.
8. Ручная проверка одного реального транскрипта: выборочно по репликам нет пересказа и потери смысла (глаза постановщика).
9. В репо не попадает проектная специфика потребителя: фикстуры и примеры синтетические.
