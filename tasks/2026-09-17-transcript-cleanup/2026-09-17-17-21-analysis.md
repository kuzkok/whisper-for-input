# Скилл transcript-cleanup: чистка диаризованного транскрипта с проектным контекстом (черновик)

Дата: 2026-09-17
Статус: черновик (политика правок требует обкатки на реальных встречах до фиксации)
Смежная задача: `2026-09-17-diarize-asr-hints` (источник входа: `/diarize` с ASR-подсказками снижает долю ошибок, но не убирает их)

## TL;DR

Новый скилл рядом с `formatting-transcript/`: берёт сырой транскрипт вида `[HH:MM:SS] [SPEAKER_XX] текст` (выход `cli/diarize.sh`) плюс файл проектного контекста и выдаёт причёсанный транскрипт: имена вместо `SPEAKER_XX`, исправленные ASR-ошибки терминологии, пунктуация. Отдельный скилл, а не режим `formatting-transcript`, потому что их политики правок несовместимы: у formatting-transcript Iron Law «ни одного изменённого слова», здесь исправление слов — вся суть. Черновик: границы «что можно править» сформулированы, но не обкатаны.

## Контекст

Реальные проблемы свежего транскрипта встречи (40 минут, 6+ спикеров):

- спикеры: часть `SPEAKER_04` / `UNKNOWN` не сопоставлена, при этом контекст реплик опознаёт человека (обращения по имени, ответы);
- терминология: «аргиз» → РГИС, «ни ромка» → «ни рамка», «кувер/кубер» → Kubernetes, «токер» → Docker, «обмордочка» → веб-морда, «верталка» → виртуалка, «айдичник» → ID-шник;
- англицизмы распознаны кириллицей там, где должны быть латиницей;
- локальные слипшиеся куски без пунктуации (целая реплика одним потоком);
- при этом основная масса текста уже нормальная — чистка точечная, не сплошная переписка.

`formatting-transcript` (SKILL.md: `formatting-transcript/SKILL.md`, скрипт `formatting-transcript/format_transcript.py`) решает другую задачу: монолог без пунктуации → статья, каждое слово сохраняется. Его верификация ±2% по словам (`format_transcript.py:132`) здесь неприменима — слова меняются намеренно.

## Граница политик

| | formatting-transcript | transcript-cleanup |
|---|---|---|
| Вход | монолог, автокапшены | диаризованная встреча |
| Слова | не менять вообще | исправлять ASR-ошибки по глоссарию и контексту |
| Структура | произвольные абзацы | реплики с таймкодами сохраняются как каркас |
| Сомнительное | — | не править без опоры; неопознанный спикер остаётся SPEAKER_XX |

## Дизайн-решения

- Каркас на выходе = каркас на входе: `[HH:MM:SS] [Имя] текст`, число реплик и множество таймкодов не меняются. Реплика — атом: не склеивать соседние, не удалять, не разрезать.
- Подстановка имён: из контекст-файла (прямое соответствие `SPEAKER_04 → Имя`) плюс вывод из содержания (к кому обращаются, кто отвечает). Нет опоры — спикер остаётся как был; угадывать имя нельзя.
- Правки текста: термины/аббревиатуры по глоссарию, англицизмы латиницей, очевидные омофонные ошибки (малая редакционная дистанция), пунктуация и заглавные. Пересказ, сокращения, «улучшение» стиля — запрещены.
- Контекст-файл — свободный markdown с секциями про спикеров и глоссарий; скилл про конкретные проекты ничего не знает, вся специфика приезжает через этот файл.
- Механика — по образцу formatting-transcript: python-скрипт (stdlib), чанки, `claude -p --tools ""` c JSON-схемой (`format_transcript.py:38-63` — образец вызова). Отличия: чанкование по репликам (не по строкам, реплику не резать), контекст-файл подмешивается в каждый вызов, перекрытие между чанками — целые реплики с краёв.
- Верификация структурная, а не по словам: число реплик и таймкоды выхода == входу; расхождение → ненулевой exit code. Длина текста реплик — мягкий ориентир для ручной выборочной проверки, не гейт.

## Задачи (по приоритету)

1. `критично` — `chunk-prompt.md`: политика правок (можно/нельзя, примеры реальных ASR-ошибок из раздела «Контекст»), формат входа/выхода, правило про неопознанных спикеров.
2. `критично` — `cleanup_transcript.py`: чанкование по репликам, вызов `claude -p` по образцу `formatting-transcript/format_transcript.py:38-121`, структурная верификация (реплики/таймкоды), отказ перезаписывать существующий выход.
3. `важно` — `SKILL.md`: триггеры («почисти транскрипт встречи», «подставь имена спикеров», «исправь термины»), когда НЕ использовать (монолог без диаризации → formatting-transcript), формат контекст-файла с примером.
4. `желательно` — тесты без реального LLM: фикстура-транскрипт с SPEAKER_XX и ошибками, мок `claude -p`, проверка чанкования и верификации (по образцу `formatting-transcript/tests/`).
5. `желательно` — обкатка на 2-3 реальных встречах с разными глоссариями; найденные нарушения политики — обратно в chunk-prompt. По итогам снять статус черновика.

## Критерии приёмки

1. На транскрипте с `SPEAKER_04` и контекст-файлом, где спикер опознан, выход содержит имя; спикер без опоры в контекст-файле остаётся `SPEAKER_XX`.
2. Число реплик и множество таймкодов на выходе идентичны входу; скрипт возвращает 0 при совпадении и 1 при расхождении.
3. Термины из глоссария контекст-файла в выходе в каноническом виде (проверка по фикстуре с заведомыми ошибками).
4. Ни одна реплика не удалена, не склеена с соседней и не разрезана (следует из критерия 2, проверяется тестом верификации).
5. Тесты скрипта зелёные с замоканным `claude -p`.
6. Ручная проверка одного реального транскрипта: выборочно по репликам нет пересказа и потери смысла (глаза постановщика).
